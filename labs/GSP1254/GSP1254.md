# Exploring Memorystore for Redis Cluster - GSP1254

## Overview

This guide walks through the three assessed activities in **Exploring Memorystore for Redis Cluster (GSP1254)**: connecting to a Redis Cluster client environment, enabling append-only-file (AOF) persistence, and scaling a Redis Cluster to ten shards. The commands below are a working draft for the specific lab environment; they are **not** evidence that the Google Skills grader passed.

Official lab: https://www.skills.google/focuses/97566

### What you'll do

- Inspect the Redis client VM and discover the Redis Cluster endpoint.
- Connect with Redis tooling and perform the lab's client/RedisSim exercise (40 points).
- Configure AOF persistence with an every-second synchronization policy (30 points).
- Scale the cluster to ten shards (30 points).

## Setup and requirements

### Before you click the Start Lab button

Use the temporary Google Cloud credentials supplied by the official lab after starting it. Open the lab's Google Cloud Console link in a private browser session when appropriate. Do **not** use your personal production project, publish the temporary credentials, or reuse a project ID from somebody else's lab.

This guide assumes that the lab provisions a Redis Cluster and a client VM. The exact cluster name, client VM name, network and RedisSim command must be confirmed against your own active lab instructions.

### Activate Cloud Shell

Open **Cloud Shell** from the Google Cloud Console and confirm the active project:

```bash
gcloud auth list
gcloud config get-value project
PROJECT_ID="$(gcloud config get-value project)"
test -n "$PROJECT_ID" && test "$PROJECT_ID" != "(unset)"
```

Discover available Redis clusters and VM instances rather than hardcoding a region or zone:

```bash
gcloud redis clusters list --project="$PROJECT_ID"
gcloud compute instances list --project="$PROJECT_ID"
```

Set the resource names and locations to those **actually shown in your lab**. The defaults below are only used by the accompanying draft script and must be checked first:

```bash

# Set REGION and ZONE from the lists above:
# export REGION="..."
# export ZONE="..."
```

## Task 1. Connect to and interact with Redis Cluster

Locate the cluster and inspect its details:

```bash
gcloud redis clusters describe "$CLUSTER" \
  --region="$REGION" --project="$PROJECT_ID" \
  --format="yaml(name,discoveryEndpoints,shardCount,state)"
```

Connect to the lab's Redis client VM:

```bash
gcloud compute ssh "$VM" \
  --zone="$ZONE" --project="$PROJECT_ID"
```

Inside the VM, inspect the available tools:

```bash
command -v redis-cli
command -v RedisSim || true
```

Use the **discovery endpoint address and port shown by the cluster** and the exact RedisSim invocation from the official lab page. Do not assume the endpoint is publicly reachable. The following is a **template**, not a confirmed command for this lab image:

```bash
# Replace these with values from the cluster description.
# redis-cli -c -h "$REDIS_HOST" -p "$REDIS_PORT" PING
```

The lab's RedisSim workload and its required concurrency must be performed as directed by the official instructions. The draft automation currently **does not** run RedisSim or demonstrate the concurrent client workload; this task is incomplete in the script.

## Task 2. Enable AOF persistence

Return to Cloud Shell (exit the SSH session if necessary). The lab calls for AOF persistence with synchronization every second:

```bash
gcloud redis clusters update "$CLUSTER" \
  --project="$PROJECT_ID" \
  --region="$REGION" \
  --persistence-mode=aof \
  --aof-append-fsync=everysec
```

Inspect the updated cluster:

```bash
gcloud redis clusters describe "$CLUSTER" \
  --project="$PROJECT_ID" --region="$REGION" \
  --format="yaml(persistenceConfig,state)"
```

Allow time for the operation to finish and confirm the resulting configuration in your environment.

### Test completed task

Use **Check my progress** for the AOF persistence checkpoint. Runtime and grader results have not been verified.

## Task 3. Scale Redis Cluster to 10 shards

Before scaling, follow the official lab's instructions about any RedisSim workload that must remain active. **The current script does not preserve or verify 500 concurrent clients during scale-out.**

From Cloud Shell:

```bash
gcloud redis clusters update "$CLUSTER" \
  --project="$PROJECT_ID" \
  --region="$REGION" \
  --shard-count=10
```

Read back the shard count and cluster state:

```bash
gcloud redis clusters describe "$CLUSTER" \
  --project="$PROJECT_ID" --region="$REGION" \
  --format="yaml(shardCount,state)"
```

Do not interpret a submitted update request as proof that the cluster finished scaling. Wait for the operation to complete and verify that the cluster reports ten shards.
